# PLAN_RETROFIT.md Template

Used by vibe-init Stage 7B to generate vibe/PLAN.md for a legacy project, after the spec
review, from the reviewed and verified vibe/SPEC.md.

This is a feature map, not a greenfield plan. The project already exists, so there are
no phases and no scaffolding tasks. Section 6 keeps the number vibe-add-feature looks for
("PLAN.md Section 6, Feature map"): every existing feature is listed there, marked built,
so a new feature can check what it depends on and what data already exists.

Sections 1 to 5 point to the reviewed documents instead of repeating them, so PLAN.md can
never disagree with them.

```markdown
# PLAN.md: [Project Name]

```

## Rules

- Copy feature names exactly from the reviewed SPEC.md, so TASKS.md "Completed", SPEC.md
  and this map all use the same name.
- Dependencies and shared data come only from SPEC.md and CODEBASE.md. If the code doesn't
  show a dependency, write "none observed". Never guess one.
- If SPEC.md changes later (`change:`), the map changes with it through vibe-change-spec.
  Never edit this file directly.
- On a vibe-init re-run over a PLAN.md that carries the vibe-init header, rebuild only
  "### Existing features" from the reviewed SPEC.md. Keep "### Planned features" and every
  entry in it exactly as it is (`feature:` added them, and some may still be in progress).
  A feature that already has an entry under Planned features is not listed again under
  Existing features.
